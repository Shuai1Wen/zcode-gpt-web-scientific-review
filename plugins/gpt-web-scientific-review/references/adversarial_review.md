# Adversarial Review Profile

Use after the blind result has been frozen, or when the user explicitly requests an attack on the current proposal.

## Attack the strongest version

Do not invent trivial implementation bugs. Challenge the strongest scientifically plausible interpretation of the proposal.

## Priority order

1. wrong scientific target;
2. non-identifiability;
3. leakage / information mismatch;
4. invalid generalization split;
5. model incapable of the claimed relation;
6. evaluation incapable of distinguishing success from shortcut;
7. novelty already occupied;
8. claim exceeds evidence;
9. only then: robustness and engineering details.

## Steelman requirement

For every major attack, also state the strongest defense. A criticism that survives the strongest defense deserves higher weight in adjudication.
